# ARGOS: уточнение поиска и контекст Ollama — 2026-09-19

Пользователь поручил развивать ARGOS и ранее разрешил автономную настройку локального Linux. Выбран ограниченный этап: точность восстановленной памяти и повторное использование постоянного контекста Ollama.

## Изменения

- `argos_deploy/src/mempalace_bridge.py`: повторы удаляются до выбора первых 12 уникальных Unicode-слов. Запрос `ARGOS` × 12 + `Railway` теперь сохраняет уточнение `Railway`. Ограничение 512 символами остаётся.
- `argos_deploy/src/core.py`: удаляется только точный начальный повтор `[SYSTEM] IDENTITY_ANCHOR` из истории Ollama. Цитаты, уникальные инструкции, summary, диалог и память сохраняются; API `DialogContext` не меняется.
- Постоянные правила располагаются до изменяемых CPU/RAM, квантового состояния и истории. Статус продолжает вычисляться для каждого запроса.
- CI запускает новый `test_ollama_prompt_context.py`; тесты SQLite дополнены случаями повторов на русском/английском, 12-го уникального слова и границы 512 символов.

Семантический поиск не добавлен. Чтение SQLite остаётся read-only; лимиты 200 кандидатов, 4096 символов документа, 10 результатов и времени сохраняются. Базовая модель, лимит ответа 128, провайдеры, авторизация и облачные сервисы не изменены. Локальное окно контекста расширено отдельно после измерений, описанных ниже.

## Исправление переполнения локального контекста

Реальные запросы выявили дополнительную причину: при окне 2048 токенов Ollama обрезал запросы 3277 и 2297 токенов до 1026, сохраняя лишь первые 4 токена и хвост. Это удаляло значительную часть инструкций и препятствовало повторному использованию префикса. Журнал: `truncating input prompt`, `limit=1026`, `keep=4`. Механизм подтверждён в [Ollama v0.34.2](https://raw.githubusercontent.com/ollama/ollama/v0.34.2/llm/llama_server.go).

После правильных ответов `6+6 → 12`, `7+7 → 14`, `8+8 → 16` локальная модель `argos-local` пересоздана из уже загруженной `qwen2.5:1.5b` с `num_ctx=4096`; `num_predict=128`, `num_thread=2`, `temperature=0` сохранены. Новые веса не скачивались.

`/root/argos-runtime/ollama/serve.sh` согласован с окном 4096; `argos.env` задаёт `OLLAMA_TIMEOUT=600`; `argosctl.py` вычисляет HTTP timeout как значение этого параметра +60 секунд. Старые файлы сохранены в том же каталоге отката; файл env остаётся private0600. Обе службы перезапущены, health ready=true.

Окно 4096 вмещает измеренные исходные запросы, но не гарантирует вместимость произвольно длинной будущей истории. Холодный запрос теперь обрабатывает больше контекста; скорость первого ответа может снизиться. Для возврата прежней конфигурации вернуть `argos.env`, `argosctl.py`, `ollama/serve.sh` из каталога отката, пересоздать `argos-local` из `qwen2.5:1.5b` с `num_ctx=2048` и прежними остальными параметрами, перезапустить обе службы.
