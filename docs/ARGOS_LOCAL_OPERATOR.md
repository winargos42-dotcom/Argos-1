# Локальный ARGOS: управление и восстановление

Панель: <http://127.0.0.1:8080/ui>. Введите существующий `ARGOS_MCP_API_KEY` из приватного файла конфигурации вашей установки. Ключ не добавляется в URL и не сохраняется в браузерном хранилище. После обновления страницы требуется повторный вход.

В панели доступны задачи, поток ответа, история, отмена, поиск памяти и явное сохранение нового факта. Вычисления вроде `125 * 8` выполняются без модели. Обычные ответы модели на этой машине могут занимать несколько минут.

## Службы

```bash
systemctl --user status argos-local.service argos-ollama.service
curl --fail http://127.0.0.1:8080/health
/root/.local/bin/argos status
```

После перезапуска дождитесь `ready: true`. `/health` и HTML `/ui` доступны без ключа; данные `/api` и MCP требуют bearer-авторизацию. Локальная служба слушает loopback. Публикация панели в интернете требует отдельной настройки HTTPS и проверки облачного ключа.

## Хранилища

Настройки находятся в `/root/argos-runtime/argos.env` с правами `0600`. Не коммитьте этот файл и не включайте его в отчёты.

| Настройка | Назначение |
|---|---|
| `ARGOS_MEMPALACE_SQLITE_PATH` | Исходная восстановленная память, открывается только для чтения |
| `ARGOS_MEMPALACE_INDEX_PATH` | Производный поисковый индекс всей восстановленной памяти |
| `ARGOS_MEMPALACE_FACTS_PATH` | Отдельное хранилище новых фактов |
| `ARGOS_TASK_DB_PATH` | Приватная история задач |

Индекс содержит SHA-256 источника и показывает `stale`, если изменился размер или время изменения исходного файла. Проверка статуса не хеширует большую базу при каждом поиске. Для перестроения используйте `src.memory_index.build_index(source_path, index_path)` из окружения приложения. Исходная база и целевой индекс должны быть разными файлами; подмена хранилища фактов индексом запрещена.

Очередь выполняет одну задачу за раз. Отмена ожидающей задачи предотвращает запуск. Отмена выполняющейся задачи действует в точках проверки и закрывает поток Ollama; выполненное файловое действие не откатывается. При перезапуске незавершённые задачи получают `interrupted` и не запускаются повторно автоматически. Хранятся последние 1000 завершённых задач. Это один процесс службы; несколько экземпляров с одной базой очереди не поддерживаются.

## Проверка и установка исходников

Команды выполняются из `/root/argos-improve`. Полная проверка измеряет рабочее дерево `argos_deploy/src`; порог 30% не заменяется покрытием только новых файлов.

```bash
/root/argos-recovery-venv/bin/python scripts/test_deployed_app.py --output /tmp/argos-app-coverage
/root/argos-recovery-venv/bin/python -m pytest tests/test_argos_release.py -q
```

Для установки сначала зафиксируйте проверенную версию в Git. `BASE_COMMIT` должен соответствовать исходникам, уже установленным в runtime. Команда `plan` проверяет это до записи.

```bash
/root/argos-recovery-venv/bin/python scripts/argos_release.py plan --repo /root/argos-improve --runtime /root/argos-runtime/app --base-ref BASE_COMMIT --output /root/argos-runtime/releases/CHANGE.json
/root/argos-recovery-venv/bin/python scripts/argos_release.py apply --manifest /root/argos-runtime/releases/CHANGE.json
systemctl --user restart argos-local.service
```

Утилита устанавливает только разрешённые файлы приложения, проверяет хеши исходников и runtime, сохраняет старые файлы и выдаёт путь к receipt. Она не меняет env, базы, службы и облако. Замена атомарна для отдельного файла; транзакция при внезапном отключении питания не гарантируется. Перед изменением env сохраните отдельную приватную копию.

## Откат

```bash
/root/argos-recovery-venv/bin/python scripts/argos_release.py rollback --receipt /root/argos-runtime/releases/CHANGE.receipt.json
systemctl --user restart argos-local.service
```

Откат откажется перезаписывать файлы, изменённые после установки. Если менялась конфигурация, восстановите соответствующую приватную резервную копию перед перезапуском. Новые базы фактов и задач можно сохранить для повторной установки; откат исходников их не удаляет.

После установки или отката проверьте ready, вход в панель, `2+2`, поиск памяти и историю задач. Живой ответ облака, наличие оборудования и поведение внешних провайдеров требуют отдельных проверок.
