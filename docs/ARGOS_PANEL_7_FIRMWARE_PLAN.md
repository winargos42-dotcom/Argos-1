# ARGOS Panel 7" — план прошивки (Waveshare ESP32-S3-Touch-LCD-7)

Статус: планирование, прошивка ещё не написана и не залита. Ничего в этом
документе не подразумевает, что что-то уже работает на плате.

## Контекст

Прежняя ESP-S3 ARGOS (аватар, меню, динамик/микрофон, музыка с SD, голосовой
канал, прошивка 2.2.61) была кастомным форком открытого проекта
[xiaozhi-esp32](https://github.com/78/xiaozhi-esp32), собранным на ПК Orion
(`F:\debug\argoss\xiaozhi-server`). Сам исходник этого форка **не найден в
этом git-репозитории** — проверены все 26 веток, совпадений нет (тот же
результат, что и с протоколом SPR2801, см. `AGENTS.md`, запись
2026-09-23). В репозитории есть только Python-обвязка со стороны ARGOS Core:

- `src/skills/esp32_usb_bridge.py` — serial-мост к ESP32
- `argos_deploy/src/factory/flasher.py` — обёртка для прошивки
- корневой `platformio.ini` — целится в generic `esp32dev` +
  `TFT_eSPI`/`XPT2046` (резистивный тач) — это осколок другого, более
  раннего проекта, к новой 7" панели (ёмкостный тач, RGB-параллельный ЖК)
  отношения не имеет.

Решение (подтверждено пользователем): не пытаться восстанавливать
утраченный форк, а взять чистый upstream `xiaozhi-esp32` как базу — как и с
SPR2801-шимом, считаем старый код утраченным и строим заново, перенося в
новую прошивку функции и модульную структуру из плана ниже.

## Найденная плата в upstream

`xiaozhi-esp32` уже содержит готовую конфигурацию:

```
main/boards/waveshare/esp32-s3-touch-lcd-7c/
├── config.h
├── config.json
├── esp32_s3_touch_lcd_7c.cc
├── waveshare_audio_codec.cc
└── waveshare_audio_codec.h
```

Подтверждено по содержимому `config.h`/`config.json`:

| Параметр | Значение в upstream `7c` | Карточка платы пользователя |
|---|---|---|
| Экран | 800×480, RGB565, 16-bit шина, VSYNC/HSYNC/DE/PCLK | 800×480 |
| Аудио-кодеки | ES8389 (выход, I2C 0x20) + ES7210 (вход) | динамик/микрофон — совпадает по роли |
| I2C | SCL=48, SDA=47 (кодеки + IO-экспандер) | I²C есть на плате |
| IO-экспандер | CH32V003 — управляет подсветкой и touch-reset | — |
| Touch IRQ | GPIO 4 | сенсорный экран есть |
| **Flash** | **32 MB** (`CONFIG_ESPTOOLPY_FLASHSIZE_32MB`) | **8 MB Flash + 8 MB PSRAM** |

**Несовпадение по Flash — единственный открытый вопрос.** Скорее всего это
другой SKU/ревизия той же физической панели у Waveshare (дисплей/тач/аудио
— то же самое железо, отличается только объём флеша на модуле ESP32-S3).
Пины дисплея/тача/аудио с высокой вероятностью подойдут без изменений;
`CONFIG_ESPTOOLPY_FLASHSIZE_*` и таблицу разделов (`partitions/v2/32m.csv`)
нужно будет подогнать под реальный чип.

**Не подгоняем это вслепую.** Первый шаг по плану — `esptool ... flash-id`
на реальной плате (см. `scripts/argos-home-diagnostics.sh` и раздел
"Этап 4" исходного плана) — даст точный размер flash/PSRAM и chip revision.
Вендорить и адаптировать upstream-проект есть смысл только после этого.

## Соответствие предложенной модульной структуры и upstream-дерева

Пользовательский план верно ставит цель (аватар + голос + IoT-шлюз +
автономность + модульность), но `xiaozhi-esp32` — активно поддерживаемый
проект с собственной устоявшейся структурой каталогов. Чтобы не потерять
возможность подтягивать апстрим-обновления, ARGOS-специфичный код стоит
класть **поверх** структуры upstream, а не переименовывать её каталоги под
диаграмму из плана:

| Из плана пользователя | Ложится в upstream как |
|---|---|
| `ui/avatar.cpp`, `ui/home.cpp`, ... | LVGL-экраны в `main/display/` (upstream уже использует LVGL) — новые экраны как отдельные файлы рядом с существующими |
| `argos/core_client.cpp`, `events.cpp`, `commands.cpp` | новый компонент `main/argos/` — единственная точка входа во внешний ARGOS Core/HA/MQTT, специфичная для нас, не апстримная |
| `protocols/mqtt.cpp`, `websocket.cpp` | upstream уже имеет MQTT/WebSocket транспорт для голосового протокола — переиспользуем, не дублируем |
| `protocols/modbus.cpp`, `can.cpp`, `i2c.cpp`, `uart.cpp` | новые компоненты `main/protocols/*` — этого в upstream нет, пишем с нуля именно под RS-485/CAN/I²C/UART разъёмы платы |
| `hardware/display.cpp`, `touch.cpp`, `audio.cpp`, `sdcard.cpp` | уже есть в board-конфиге `esp32-s3-touch-lcd-7c` — переиспользуем как есть |
| `ota/updater.cpp` | upstream уже имеет OTA-механизм — проверить, есть ли в нём rollback (ESP-IDF поддерживает app rollback через `esp_ota_mark_app_valid_cancel_rollback` из коробки) до того, как писать свой |

## План действий по шагам (без гадания вслепую)

1. **Диагностика на месте.** `scripts/argos-home-diagnostics.sh` на X230 —
   уже сделано (ждём вывод).
2. **Определение порта ESP32** (`ls /dev/ttyACM*`/`ttyUSB*`, `lsusb`).
3. **`esptool ... flash-id`** — получаем реальный размер flash/PSRAM и
   ревизию чипа. Снимает вопрос "32MB vs 8+8MB" окончательно.
4. **Бэкап заводской прошивки** (`esptool ... read-flash 0x0 <размер>
   factory-backup.bin` + `sha256sum`) — обязательно до перепрошивки.
5. **Вендоринг upstream `xiaozhi-esp32`**, зафиксированный на конкретном
   коммите (не "main" вслепую), с адаптацией `config.json` под реальный
   flash/PSRAM из шага 3.
6. **Сборка stock-конфигурации** `esp32-s3-touch-lcd-7c` как есть — цель
   первого прохода: убедиться, что экран/тач/аудио/Wi-Fi реально работают
   на этой конкретной плате, прежде чем добавлять что-то своё.
7. Только после этого — ARGOS-слой: `main/argos/`, `main/protocols/{modbus,
   can,i2c,uart}`, MQTT-топики (`argos/panel7/...`), экран аватара с
   привязкой к статусу ARGOS Core/HA/MQTT, автономный режим при недоступном
   X230.

## Требование к прошивке (зафиксировано из обсуждения)

- Панель никогда не коммутирует силовую нагрузку напрямую — только
  команда → HA/MQTT/RS-485 → реле → **подтверждённое фактическое
  состояние** → обновление UI. Кнопка "Свет" не переключается визуально по
  нажатию, а только по приходу нового состояния устройства.
- При недоступности X230/ARGOS Core панель обязана продолжать: показывать
  сеть/датчики/CAN/RS-485-устройства локально, показывать ошибки,
  переподключаться сама.
- OTA — обязательно с rollback (ESP-IDF app rollback), не "втупую перезаписал
  и молись".
